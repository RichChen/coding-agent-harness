### 公开目标验收：先证明检查能判对，再让模型做题

从原始 issue 和固定基点的公开文档、源码独立准备最小文档项目及 runner，不读取 gold patch、隐藏测试或私有任务记录。三种场景及检查源码均在模型运行前公开、冻结：

| 场景 | 期望 | 防止什么误判 |
| --- | --- | --- |
| 新鲜 EPUB 构建，默认关闭 viewcode EPUB 功能 | 不生成或打包模块源码页 | 确认默认行为和基础构建可用 |
| 先 HTML，再 EPUB；共享 doctrees，分别使用输出目录；默认关闭及显式 `False` | HTML 有源码页；EPUB 不生成或打包源码页 | 覆盖实际跨 builder 问题，不能每次重置 doctrees 绕开故障 |
| 显式 `True` 的 EPUB 构建 | 确实生成并包含预期源码页 | 防止直接禁用全部 viewcode 功能获得通过 |

各独立场景重置状态；检查 EPUB 输出目录和归档内容。付费前须确认原始基点在跨 builder 场景出现与 issue 一致的行为失败、正向对照有效。导入异常、缺依赖、构建未成功或空产物均不能算目标失败复现。若无法做到，暂停这题，不先花钱试模型。

**采用最小接法：B 保持 `regression_only`；公开目标检查在最终候选封存后单独执行。** 现有 `SphinxProfile` / `DockerReplicaExecutor` 固定使用 `tests/test_util.py`，也不接纳真实目标的预期失败基线。本轮不修改它们的证据语义，也不把真实目标伪装为人工 fixture。

单独的宿主 runner 复用现有候选物化和 Docker 基础能力，在同一固定镜像的新副本内执行。检查材料与构建产物放在候选源码之外；核验最终 `candidate_id`、manifest、实际 Sphinx 导入来源，使用相同冻结检查包分别检查原始基点和最终候选。它是一个需要实现、验收的小入口，不能直接复用硬编码 selector 的执行器。

目标检查结果单列为 `public_target_check`，不冒充生产 B 的 `ValidationRecord` 或 SWE-bench 独立评分；原有 `solved=null` 不因此改成 SWE solved。目标验收结束后不把失败回灌给模型追加一次尝试。模型事先得到完整公开需求和验收场景，可以在原预算内自行复现；不强制它必须调用检索或触发宿主反馈来制造展示轨迹。

## 5. 预算：金额从哪里来

### 5.1 官方价格依据

2026-10-30 核对 [DeepSeek 中文官方价格页](https://api-docs.deepseek.com/zh-cn/quick_start/pricing/) 与 [美元官方价格页](https://api-docs.deepseek.com/quick_start/pricing/)：`deepseek-flash` 当前对应 `DeepSeek-V4.1-Flash-1017`。人民币高峰价为无缓存输入 **2 元/百万 token**、输出 **8 元/百万 token**；美元分别为 **$0.30 / $1.20**。本方案一律按高峰、缓存未命中测算，不靠优惠或缓存才能控制成本。账本美元价格表对应每千 token `prompt_per_1k: 0.0003`、`completion_per_1k: 0.0012`。

开跑当天重查价格和模型映射。记录服务返回的信息，但别名或 fingerprint 都不能保证后端长期固定；未返回 fingerprint 时如实记未知，不杜撰可锁定版本。

### 5.2 场景计算与申请额度

人民币估算公式：`2 × 实际输入token / 1000000 + 8 × 实际输出token / 1000000`。

| 场景 | 假设用量 | 峰值无缓存估算 |
| --- | --- | ---: |
| 较短运行举例 | 累计输入 96,000；输出 8,000 | 0.256 元 |
| 较长运行举例 | 累计输入 480,000；输出 40,000 | 1.28 元 |
| 用满任务规划额度的算术情形 | 输入+输出 1,600,000；输出最多 `24 × 4096 = 98,304`，其余为输入 | 3.789824 元 |
| 两次 probe 的算术情形 | 输入+输出共 10,000；输出最多 `2 × 512 = 1024` | 0.026144 元 |
| 任务 + probe 合计 | 至多 26 次请求尝试；输出规划最多 99,328；账本 token 阈值合计 1,610,000 | **约 3.82 元** |

这些是用量假设下的金额，不是实测平均费用或账户硬上界。**建议首轮授权总额 5 元**：规划约 3.82 元，余量留给计费误差与异常核对，不拿来追加题目、自动重跑或换模型。任务美元账本 $0.60 是程序控制参数，人民币资金预算仍按官方人民币价和实际账单核对，不使用臆测汇率换算。

本机 CPU/Docker、已存在镜像不新增云资源租金；不拉新镜像、不安装新依赖或租 GPU。若复现发现必须新增这些资源，先报告具体缺口。5 元不包含本项目开发/审查所用 Codex 会话的订阅或账户消耗，此项无法从仓库推算；分工复用现有会话，避免重复扫描和重复付费求解。

### 5.3 限额实际能保证什么

当前 [模型预算账本](../../src/policy/model_budget.py) 在每次尝试前预留，正常返回后按 provider usage 结算；重试也占调用数。但输入估算来自 JSON UTF-8 字节数除以 4，usage 缺失时只保留预估，最终一次结算可能超过阈值。因此 `max_cost_usd` / `max_tokens` 不能当作供应商账户的绝对限额。

本次采用单实例、0 重试、明确调用次数、短 probe、未知计费即停及金额余量。付费前确认无重复任务启动；计费未知时查清已发生的调用，不能以“没收到回复”为零成本。要获得供应商账户绝对封顶需供应商侧支持，本计划没有实现或声称具备这一点；若作者要求绝对不超额，应先落实账户侧可核验限额后再运行。
