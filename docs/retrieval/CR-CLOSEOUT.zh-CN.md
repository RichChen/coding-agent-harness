# CR 收尾：代码检索与 Agent 接入

日期：2026-10-29。读者：阶段末复核的 Codex，以及项目作者。总体方案见 [PLAN](PLAN.zh-CN.md)。

CR 线到此结束。CR-3 暂缓，原因和启动前必须修正的两处写在 PLAN 第 5 节。

## 1. 做了什么

| 层 | 内容 | 结果文件 |
|---|---|---|
| CR-1 | 仓库快照读取、AST 切块、blob 缓存、BM25、代码向量、RRF 融合；dev 选参后冻结，400 道 test 只评一次 | [CR-1-RESULTS](CR-1-RESULTS.zh-CN.md) |
| CR-2 | 检索接入 harness：预取（P）、检索工具（T）、给出正确文件（O）对无检索（N），56 题 × 4 组 × 5 次 = 1120 次同期交错运行 | [CR-2-RESULTS](CR-2-RESULTS.zh-CN.md) |
| CR-2e | 新 system prompt 区分 `retrieve_code` 与 `search_code`；6 题 × 2 次开发检查；离线演示脚本 | [CHECKPOINT-CR-2e-a](CHECKPOINT-CR-2e-a.md)、[demo/](demo/) |

## 2. 结论和可以对外说的话

| 结论 | 证据 | 不能说成 |
|---|---|---|
| 混合检索的文件级 Hit@5 从 67.5%（BM25）到 85.8%，MRR 0.520 → 0.684 | CR-1，400 题，按题配对与按仓库 cluster bootstrap 都不含 0 | 修复率提升；hybrid 一定优于纯 embedding（文件级未检出差异，函数级 +7.5 个百分点） |
| 预取没有让定位更早；给出正确文件后，修复率未检出变化 | CR-2，P−N、O−N | 定位不是瓶颈（只能说这批题上继续优化定位的空间有限） |
| 原提示下检索工具 0/280 被调用；明确分工后开发检查 6/12 调用 | CR-2 T 组、CR-2e | 模型学会了按需检索；两个数字可以直接比较（题目和提示都不同） |
| 同一模型别名下，相同提示的解出率 68.5% → 45.7% | A5 B0 与 CR-2 N 的事后比较，没有预注册 | 下降全部来自模型更新 |

## 5. 留下的问题

- 查询怎么写：单题观察到短查询远好于 issue 全文（AUDIT-CR-2e-a 第 3 节），可以离线验证。
- 模型别名漂移：没有可以固定版本的写法，只能记录 `system_fingerprint`。
- Cursor 执行环境会重复执行命令：出现过三次，靠单实例锁和"已完成就拒绝"挡住了。
